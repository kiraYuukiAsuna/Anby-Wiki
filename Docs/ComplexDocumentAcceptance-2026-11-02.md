# 复杂文档与供应商用量验收（2026-11-02）

本轮修复扫描件遗漏、PDF 旋转与区域定位，并补齐 Kernel 纠正重试、截断、
失败和取消调用的逐次用量记录。初次语料验收在生产宿主机的独立容器与网络内执行，
使用账号现有 `deepseek-flash` 配置；仅经领域配置服务读取运行配置，
不创建生产账号、来源、任务或 Proposal，不部署业务版本。
该阶段生产保持 `36cb429225c0`；后续发布结果见本文末节。

机器可读证据见 [JSON 审计](ComplexDocumentAcceptance-2026-11-02.json)；
[2026-11-01 报告](ComplexDocumentAcceptance-2026-11-01.md)保留历史压力与失败数据。

## 修复内容与身份

- PDF Adapter v3、图片 Adapter v2、`document-page-layout-v2` 与
  `document-region-analysis-v2`：移除外缘空白、按每页 `/Rotate` 还原识别方向，
  合并同列同章节的相邻正文；裁图保留水平 64/1000、垂直 32/1000 的边缘安全区。
  Citation 定位记录实际裁图并映射回原始旋转图，右/下边缘向上取整。
  没有引入独立 OCR 或语义布局运行时。
- 布局 Prompt 明确使用 0～1000 的归一化坐标；Schema 和页内边界继续严格校验，
  不把越界区域裁成合法值后放行。
- Kernel 协议 2 使用 `attempt_started`、`attempt_finished` 与 `result` NDJSON
  事件。每次物理请求的 UUID 作为 `X-Client-Request-Id` 发往供应商，同 ID 写一条
  Usage；不假定该请求头具有供应商幂等语义。纠正重试携带待修正 JSON 与校验路径，
  失败及截断输出的已报告 Token 同样计入，Go 不叠加 Kernel 已完成的重试。
- 调用取消时保留已收到的回执，未报告用量追加 `:usage_unreported`；这些 Token
  只是已知下界。Usage 保存使用独立 Context，总期限 5 秒；保存失败进入 Trace，
  不覆盖原始模型失败原因。首次回执前断连、进程强制退出、审计落库失败以及取消后
  供应商继续计费仍需外部账单核对。

## 真实复杂长文

使用官方 [Attention Is All You Need](https://arxiv.org/pdf/1706.03762) 的
15 页 PDF，SHA-256 为
`bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697`。
验收区分原生文字保留和视觉识别：原生字符回填不能证明图中标签识别成功；
表格、图示与注意力可视化需核对来自 `vision_page` 的区域，而不是补充原文。
单轮限制最多 100 个逻辑调用、160 次供应商尝试；这是本次试验的安全边界，
不是任意 15 页文档的生产容量承诺。

最终裁剪版本首次运行在第 5 页失败：三次布局输出均违反
`$.elements[16].region.y (maximum)`，31.116 秒后整份解析终止，无部分制品。
29 条物理尝试均有审计记录，已知输入 44,720、输出 9,184 Token；
两条并行取消记录用量未知，因此与供应商边界的 Token 合计不相等，不能按零成本通过。
之后补上纠正重试的待修正 JSON 上下文并复跑，98.499 秒完成 15 页解析，
内存峰值 331.8 MiB；90 次物理请求、131,942 输入/26,159 输出 Token，
全部 ID/用量与供应商边界回执对应，零未知用量，22 个持久图像区域均在原图边界内。

逐页核对同版 Poppler 的原生字符范围，15/15 页共 33,470 个非空白字符全部保留，
每个保存的范围与原文逐字相等。单独检查 `vision_page`：第 3/4 页架构图标签，
第 6/8/9/10 页表格关键值，以及第 13/14/15 页图示标签/标题，共 9/9 组通过；
例如 Transformer big 的 28.4/41.8 和 WSJ F1 的 91.3/92.7 均来自视觉表格。
第 4 页 `SoftMax` 大小写依据原图复核；不会从原生补充分片借用标签证明视觉成功。

原有“输出分片直接拼接”局部文字检查仍为 12/15、小字代理检查为 13/15，
这些失败诊断保留在 JSON。原生区域和补充分片的顺序使某些跨片段样本文字不再连续；
完整字符范围覆盖只证明原文未丢失，不能把这两项解释为已通过阅读顺序验收。
模型仍报告多处裁剪片段不完整、区域文字未匹配与第 13 页零置信度的空白正文区域；
未匹配视觉正文由原生文字补充分片保留，没有据此宣告完整复杂长文质量门槛通过。

## 故障与费用边界

真实 HTTP 夹具经过 Kernel→Go Gateway 验证十个场景：
Schema 纠正、截断分别两次；429、供应商超时和 503 分别三次；
额度耗尽一次；调用方期限和主动取消分别一次；缺少用量一次；
非法输入 Schema 零次供应商调用、零条 Usage。所有发出的请求 ID 均与 Usage 对应。
纠正和截断的 Token 合计分别为 16/10 与 24/8,199；未提供用量的响应明确标为未知。
这些是受控 HTTP 故障，不替代真实供应商 429、额度耗尽及告警接收。

[DeepSeek 英文价格页](https://api-docs.deepseek.com/quick_start/pricing)
在 2026-11-02 列出 DeepSeek-V4.1-Flash-1017：
高峰每百万输入缓存命中 0.006 USD、未命中 0.3 USD、输出 1.2 USD，
非高峰为一半。以全部输入缓存未命中及高峰单价估算固定回归上界，
不表示供应商已结算账单；中文价格页仍列旧模型和不同币种，本轮不假定汇率或对应关系。
供应商返回模型名仍为 `deepseek-flash`，不能凭别名证明版本固定。
对应固定四页每轮估算 0.00833～0.00935 USD、五页 0.01089～0.01098 USD；
15 页论文成功轮为 0.07097 USD。此前失败、其他探索试验及共享账号调用不在这几个
成功轮的金额内，不能把它们当成本次全部实验费用。

官方 `/user/balance` 只读探针返回 200 且可用；第一次失败试验前后共享账号净扣减
0.12 CNY。共享账号余额变化不能分配到单次请求，也不能用于推导美元账单；
其他试验和账号调用另计。
