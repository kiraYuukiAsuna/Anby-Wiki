# 复杂文档持续压力与供应商边界验收

> 日期：2026-11-01。目标服务器：8 vCPU、7.75 GiB、无 Swap，与生产共享宿主机。
> 生产业务版本 `94546a7`；修复使用本地工作区 Linux API 二进制和 Kernel 源文件，
> 只装入隔离容器，尚未提交或部署到生产。

## 结论

近上限上传、客户端中断/重试、异常退出恢复和多 Worker 领取可以验收；
当前两阶段解析器的质量与供应商成本门禁仍未通过。真实七语言固定语料已经执行，
结果低于历史整页基线，不能因为服务器规格而豁免识别遗漏。真实限流/配额耗尽、
告警接收和账单核对仍缺证据，受控 HTTP 故障不能替代这些场景。

本轮修复了三个实测问题：

- API 被强制终止后，持久上传目录遗留约 10.2 MiB multipart 文件，重启不会清理。
  API 现在持有独立临时目录的进程锁，启动时只删除锁已释放的旧目录；客户端中断和
  强制终止后重启均清零。真实子进程测试确认另一进程的在途文件不会被删除。
- 双 API 同时首次上传同名资产时，缺少可锁的资产行，一个请求触发唯一键冲突/500。
  领域 Repository 现在先取得 Wiki/名称的事务级锁，再查行、创建和去重。
- 供应商 `insufficient_quota` 被当成临时限流重试三次。Kernel 现在对明确的配额错误
  返回 `quota_exhausted/temporary=false`，一次请求后停止；任务诊断提示恢复额度，
  `retryable=false`。其他 429 和超时继续有限重试，不传出供应商原始消息。

## 两阶段与历史整页比较

使用相同 `deepseek-flash`、固定四页合成扫描 PDF，对比当前工作区 Parser 与
`18944a7` 的真实整页 Parser；各自在相同 Worker 运行时中调用独立 Kernel。
配置请求期限 180 秒、最多三次尝试；先行测试显式限制一次尝试。
每个解析容器限制 1 CPU、768 MiB。历史渲染最长边 2000，当前 4000，
布局请求最长边 1600、裁剪请求 2000，这是实际版本差异，未人为统一。
供应商名称是配置中的模型别名，不是可证实的不可变模型快照。

| 指标 | 历史整页：四页 | 当前两阶段：四页 | 当前两阶段：旋转重复五页 |
|---|---:|---:|---:|
| 解析完成 | 是 | 是 | 是 |
| 正文/表格逐字断言 | 47/47 | 43/47 | 46/60 |
| 完整细小脚注 | 4/4 | 3/4 | 5/5 |
| Chunk / 带区域 Chunk | 16 / 16 | 23 / 23 | 25 / 25 |
| Gateway 调用数 | 4 | 27 | 30 |
| 物理供应商请求数 | 4，无纠正重试 | 29 | 34 |
| 全部尝试输入 Token | 7,369 | 25,388 | 31,529 |
| 全部尝试输出 Token | 1,962 | 2,789 | 3,768 |
| 耗时 | 6.432 秒 | 26.246 秒 | 27.476 秒 |
| cgroup 生命周期内存峰值 | 71.9 MiB | 248.4 MiB | 296.0 MiB |

当前四页比历史整页增加 7.25 倍物理请求、3.45 倍输入 Token、4.08 倍耗时，
本轮没有证明识别或成本改善。严格文字断言失败包含标点差异和内容不完整，不能
直接称为语义召回率；区域数量增加也不代表区域覆盖改善。页码覆盖完整，
但没有独立人工矩形标注，不能给出区域 IoU。

先行的 `max_attempts=1` 受限测试分别调用 27/26 次 Gateway，
两份语料都因区域输出 Schema 不合法而整份失败、返回空解析结果；
没有输出部分成功制品。随后按三次重试设置运行得到上表结果，
纠正重试能使 Schema 合法，仍不能保证文字完整。

语料覆盖中、英、日、法、俄、西、德，含跨页表格、0/90/180/270 度旋转、
混合尺寸、重复页面和细字脚注；它没有覆盖所有真实长文、图表和极密集小区域。
固定文件、逐页断言、SHA-256 与升级/每周抽样规则已保存到
[回归语料](../backend/internal/importer/testdata/acceptance/README.md)。
发布门槛保留每轮全部断言/脚注通过，并人工检查阅读顺序和额外生成事实；
当前结果记录为失败基线，不能降低门槛。

## 持续上传与恢复

使用独立 PostgreSQL、Redis、RustFS bucket、Kernel 和两个 API，未写生产数据库、
对象存储或搜索索引。API 每进程 1 个槽位、1 CPU、384 MiB。
近上限文件为有效扫描 PDF 加尾部空白，总长 312,475,648 bytes（298 MiB）；
它验证传输、流式校验、存储及幂等，不代表 298 MiB 的复杂视觉解析。
上传后取消任务，避免这部分压力触发付费模型或生成 Proposal。

六轮双 API 连续压力共 379.143 秒，12 次 298 MiB 请求传输约 3.49 GiB，
全部返回 201，单请求 61.030～73.160 秒。其中四次新建任务、八次原幂等键重放，
重放始终复用任务 ID；首次同名并发上传也成功。每轮响应后 multipart 文件清零。
12 次满槽探针返回 503 与 `Retry-After: 1`，响应 2.35～17.98ms。
独立恢复探针按该期限等待后返回 201，同一键在另一 API 重放仍是同一任务。

185 次采样中生产就绪探针全部 200。两个 API 的 cgroup 生命周期峰值为
329.1/322.5 MiB，匿名内存采样峰值为 15.9/14.7 MiB；
各自最大临时文件 298 MiB，宿主机剩余磁盘最低 20.5 GiB，没有 OOM。
这包含磁盘文件页缓存，不能把 cgroup 总内存称为 Go 堆。首次正常客户端中断发送
约 12.25 MiB 后清零；强制终止时约 10.2 MiB 在途文件，修复后重启清零。

双 Worker 以 20 个约 1.06 MiB 的 `source_only` 文本任务验证数据库领取，
积压从 20 排空，实测最多两个 running；2.942 秒完成，每个任务仅一个 Run、
全部 succeeded。此模式不调用供应商，不能外推两份大 PDF 的同时解析容量。
临时目录锁另在目标 Linux 容器用真实子进程验证共享目录保留与强制终止后回收。

生产的旧根目录 `multipart-*` 不会被新实现按文件年龄盲删。首次升级应在停止全部旧
API、确认没有在途上传后清理遗留根文件；新目录使用进程锁自动恢复。
锁依赖本地共享磁盘的文件锁语义，不承诺 NFS 等未验收的挂载。

## 并发和供应商成本边界

上传槽位和 AI Gateway 限制仍是进程级；数据库 `SKIP LOCKED` 防重复领取，
不限制副本总数。当前生产维持 1 API/1 Worker，不启用自动扩容。
受控扩容的运维上限定义为最多 2 API/2 Worker：最多 2 个在途上传、2 个导入任务、
6 页视觉处理、8 个导入模型调用。全部副本必须计入同一配额，新增副本前先核对
磁盘、模型并发和 Token 预算；这不是自动执行的分布式限流。
账号连接测试等其他模型入口也必须另计，不能把“导入模型 8 并发”称为供应商总上限。
自动扩容/多个独立部署共享同一供应商账号前，仍需实现全局租约与供应商预算。

| 供应商场景 | 证据 | 结果 |
|---|---|---|
| HTTP 429 临时限流 | 受控真实 HTTP 端点，经过生产 Kernel | 3 次请求，约 3.08 秒后 `rate_limited/temporary=true` |
| HTTP 429 `insufficient_quota` | 同上，修复前/后比较 | 3 次临时限流 → 1 次 `quota_exhausted/temporary=false` |
| 请求超时 | 受控端点延迟，5 秒期限、3 次尝试 | 3 次请求，约 18.05 秒后 `timeout/504` |
| 真实供应商短期限 | 真实模型、图像输入、5 秒期限 | 1.011 秒成功，276 输入/5 输出 Token；没有触发真实超时 |

没有耗尽真实账户配额，也没有制造持续付费请求去触发真实限流；这些真实故障和
告警接收尚未验收。故障注入只证明传输、错误分类和有限重试行为。

成本统计发现一个实际缺口：四页 Gateway Usage 记录 27 次、23,997/2,704 Token，
供应商边界审计为 29 次、25,388/2,789；五页账本为 30 次、28,686/3,542，
边界为 34 次、31,529/3,768。Kernel 只返回最后一次成功的 Token，
Go 只记一次 Gateway attempt，纠正重试、失败和取消请求可能计费却未完整入账。
解析比较直接调用 Parser/Gateway，Usage 在隔离测试中捕获，不写业务数据库；
正常 Worker 持久化使用同一 Usage 模型与 Kernel 返回协议。
因此 `wiki_ai_tokens` 不能当账单成本或严格预算。本轮未获得供应商账单、
缓存命中分项和价格结算证据，不换算金额，也不宣布成本门禁通过。
