# ADR-0025：账号安全与独立系统管理

- 状态：已接受
- 日期：2026-11-02

## 决策

Wiki 管理员只管理所属 Wiki。新增独立 `local_account.system_admin` 权限，
不因注册、Wiki admin 角色或前端可见性自动授予。系统管理台入口 `/admin`，
全站 SMTP 在此持久化配置。系统权限不绕过私人 Wiki 成员和页面权限。
首个系统管理员由运维显式指定既有用户名，经领域服务写入并记录审计；
后续系统管理员可重新认证后在管理台授权。最后一名有效管理员不可撤销，
Wiki 用户删除也不能删除系统管理员。

初始 `admin` 账号的系统管理员权限不可撤销，共享领域写入入口同时保护管理台
与运维命令；即使还有其他管理员也不能撤销。该保护不自动授予权限。
其他系统管理员可重新认证后撤销自己的权限，仍需保留至少一名有效管理员。
管理台账号与系统审计独立按页读取，默认各 10 条，账号搜索覆盖完整列表。

个人中心 `/account` 管理邮箱验证、邮箱变更、TOTP、一次性恢复码、密码及
设备会话。邮箱变更必须先验证新邮箱；资料编辑不能直接改写邮箱。
密码恢复只允许已验证邮箱。恢复不关闭 MFA，必须同时提交验证码或恢复码。

验证链接和恢复令牌随机 256 位，数据库仅保存 SHA-256；验证链接 30 分钟、
密码恢复 15 分钟有效。邮件令牌使用 URL fragment，不进入服务端访问日志。
服务端只在 POST 确认时消费，避免邮件安全扫描器的 GET 请求触发修改。
每账号每种邮件一分钟最多一次、每日最多 20 次，公开认证路径使用敏感限流桶。

TOTP 采用 RFC 6238：SHA-1、6 位、30 秒周期，容许前后一个时间步，
账号持久记录最后消费时间步，拒绝重复使用。密码登录仅签发五分钟 MFA challenge，
不签发会话；challenge 最多五次尝试。连续五次错误身份验证锁定安全操作十分钟。
十个恢复码各有 80 位随机熵，只存哈希，单次事务消费；重新生成使旧码失效。

SMTP 密码与 TOTP 密钥使用已有 `AI_CONFIG_MASTER_KEY` 的 AES-256-GCM，
通过独立 AAD 区分 SMTP、账号安全域和账号 Actor。密钥未配置时不能启用 MFA
或保存 SMTP 密码；普通密码登录仍可使用。邮件强制 TLS/STARTTLS，
明文只允许本机测试。发件地址和 HTTPS 站点地址由系统管理员配置，
不从不可信请求 Host 推断。

安全写入仅接受本人真人浏览器会话，并重新验证密码及已启用的 MFA；
CLI Bearer 或开发头不能管理安全设置。启用/停用 MFA、修改/恢复密码、
确认邮箱变更和撤销全部会话，会撤销本人及其机器 Actor 的 CLI 凭证和授权码。
启用 MFA 为已经完成密码与 TOTP 验证的当前浏览器签发新会话，其余旧会话失效。
凭证签发、消费和撤销按 LocalAccount → Actor/Session/授权码顺序串行，
防止在途兑换绕过撤销。

测试邮件仅要求有效的系统管理员浏览器会话，无需再次验证密码或 MFA。
管理员显式填写测试收件邮箱，使用已保存的 SMTP 配置投递；服务端校验收件地址、
重新检查会话和系统权限并记录发送审计。保存 SMTP 配置仍需重新认证。

## 存量部署

遵循仓库预发布约定，不添加第五个编号迁移。新建数据库修改 `000001` 的完整
up/down；已有版本 4 数据库在发布前显式执行
`scripts/upgrade-account-security.sql` 的幂等、仅增量 Schema 补齐。
不执行生产 down，不删除账户或私人 Wiki。详见
[账号安全运维指南](../AccountSecurity.md)。

## 支持边界

支持：已验证邮箱恢复密码；验证器丢失但仍持有恢复码时登录、停用或重新绑定；
重新认证后的密码、邮箱和会话管理。操作记录 Actor、目标 Actor、动作和时间，
不记录密码、邮箱正文、密钥、令牌、恢复码或 Prompt。

不支持：邮箱与全部二次凭证同时丢失时的人工绕过；管理员代替用户恢复密码、
关闭 MFA 或读取私人 Wiki；私人 Wiki 所有者跨账号转移。需要迁移资料时，
由原所有者自行授权现有协作/导出/导入流程，仍遵循 Proposal 人工审核。
未来如承诺所有权转移，必须另行定义双边同意、身份复核、审计与不可变数据归属规则。
