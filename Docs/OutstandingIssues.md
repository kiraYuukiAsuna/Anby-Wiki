# 待解决问题

> 更新时间：2026-10-30

本文只保留尚未完成的实现、环境验收和责任确认。已交付功能统一描述在
[当前实现状态](CurrentImplementationStatus.md)，历史测试数据见
[商业验收证据](CommercialAcceptance-2026-10-11.md)。问题关闭后，将可复用的功能描述
补入相应文档，并从本文移除。

## 1. 备份恢复与人工可访问性尚未在发布环境验收

### 1.1 待验收内容

- 生产等价隔离资源的 PostgreSQL、对象存储备份恢复演练，以及 RPO/RTO 记录。
- 正文、编辑、历史、搜索、治理与所有 Hub 的完整键盘顺序、焦点、读屏器语义、
  对比度，以及断网、超时和 5xx 状态。
- 当前生产版本的全量 Projection 重建及全部 Builder 的前后状态和页面计数。
- 当前生产版本的管理员 CLI 授权码创建、兑换、受保护读取、撤销和撤销后 401 闭环。
  线上身份接口与页面入口检查不替代这项授权操作验收。

### 1.2 关闭条件

1. 在维护窗口使用远端生产等价隔离资源，显式运行 PostgreSQL 和对象存储备份/
   恢复演练并记录 RPO/RTO；保持手工灾备与日常一键部署分离。
2. 人工覆盖上述页面的键盘、焦点、读屏、对比度与网络失败状态。
3. 以当前生产版本全量重建 Projection，记录 Builder 状态与页面计数，并确认
   References 编号和多回链、Related topics 原因、Related outlines 与信息框一致。
4. 管理员从正式 `/settings/cli` 创建授权码，完成生产 CLI 兑换、受保护读取、
   后台撤销与撤销后 401 验证。

## 2. 账号恢复、邮箱验证与二次验证未完成

### 2.1 待实现内容

- 邮件发送基础设施、邮箱所有权验证和忘记密码流程。
- MFA、备用恢复码、登录设备列表与全部会话吊销。
- 账号恢复及私人 Wiki 转移的支持边界、授权和审计流程。

### 2.2 关闭条件

1. 接入邮件供应商，实现邮箱验证、验证状态和重发限流。
2. 实现一次性、短时效、只存哈希的密码重置令牌，并在重置后吊销已有会话。
3. 提供 TOTP 或 WebAuthn MFA、恢复码和登录设备/会话管理。
4. 明确账号恢复与私人 Wiki 转移的支持边界；对承诺支持的流程补齐授权和审计。
5. 在正式域名验收新增恢复与 MFA 流程，以及恢复后的登录、会话吊销和私人 Wiki 隔离。

## 3. CSRF 生产启用与证书恢复演练尚未验收

### 3.1 待完成内容

- 来源校验尚未部署到正式环境，需要完成同源浏览器写入、跨来源拒绝和 CLI 兼容性验收。
- 证书自动续期、失败告警与代理配置备份恢复尚未完成验收。
- 若启用最终客户端 IP 限流，仍需确认外层转发头清洗与 API 可信直连对端配置。

### 3.2 关闭条件

1. 验证证书自动续期、续期失败告警和代理配置恢复。
2. 部署来源校验，并验收同源登录、编辑、上传、跨来源写入拒绝、CLI 和协作路径。
3. 启用最终客户端 IP 限流前，先由外层清洗 `X-Forwarded-For`，再只把 API 的可信
   直连对端加入 `TRUSTED_PROXY_IPS`。

## 4. Meilisearch 容量与语义质量尚未在目标环境验收

### 4.1 待验收内容

- ADR-0012 定义的 10 万页面规模下，目标硬件的吞吐、P95/P99、索引任务延迟、
  全量重建时间、内存和磁盘占用。
- 固定中文查询集的语义召回质量，以及无外网环境的模型预置和失败降级策略。
- 索引配置慢任务的启动重试与超时策略，避免单次 task 等待超时导致服务退出。

### 4.2 关闭条件

1. 在目标规格上导入 10 万页面并运行关键词、过滤、混合和语义基准。
2. 记录吞吐、P50/P95/P99、索引积压、全量重建时间、内存和磁盘水位。
3. 用固定中文查询集评估语义召回，并定义无模型或模型下载失败时的显式降级策略。
4. 在目标规模下验证旧 Revision 重试不能覆盖新索引，删除 Page 会同步移除远端文档。
5. 验证索引配置启动重试与单次请求超时，避免健康服务因慢 task 轮询产生一次性退出。

## 6. 非阻断协作演进项

### 6.1 待实现内容

- 跨浏览器关闭、重载或重启的持久化离线 Yjs update 恢复。
- Presence 的 Actor 名称解析、字符位置协议与字符级编辑器 Decoration。
- 多 API 实例间的实时广播或 WorkingDocument 级连接粘性。

### 6.2 关闭条件

这些演进项不阻塞当前单 API Internal Beta，按相应后续里程碑验收：

1. 扩展离线 CRDT 恢复承诺前，持久化未确认 Yjs update，并覆盖浏览器重启后的恢复、
   重放与冲突处理。
2. 扩展协作体验时，补齐 Actor 名称、字符位置和光标装饰的协议与浏览器验收。
3. 进入水平扩展里程碑前，实现跨实例广播或连接粘性，并新增多副本 E2E。

## 8. 复杂文档持续压力与供应商成本边界尚未验收

### 8.1 待验收内容

- 当前布局识别与区域识别两阶段解析器的真实供应商识别质量、细小区域、调用量、
  峰值内存与成本对比。历史整页视觉版的验收不能替代当前解析器验收。
- 近 300 MiB 上限的长时上传、客户端重试、异常退出后的临时文件清理和服务恢复。
- 多 API/Worker 副本的全局并发与背压策略。
- 真实供应商超时、限流、配额耗尽、告警、重试、错误分类和账单成本。
- 更多语言的复杂文档质量，以及模型升级后的固定回归基线和抽样频率。

### 8.2 关闭条件

1. 使用固定语料比较当前两阶段解析器与历史基线的识别质量、区域覆盖、调用量、
   耗时、峰值内存和账单成本。
2. 执行近上限长时上传和客户端重试压力，验证磁盘水位、503 重试、异常退出残留
   清理与服务恢复；水平扩展前定义跨 API/Worker 副本的全局并发上限。
3. 用真实供应商超时、限流和配额耗尽场景验证告警、重试、错误分类与账单成本。
4. 在重复、旋转、混合尺寸和中英双语跨页表格/图表回归集基础上增加其他语言，
   并定义模型升级后的固定质量基线和抽样频率。

## 9. 提示注入判定仍可能误报合法来源

### 9.1 待解决内容

- 第一人称角色设定、引用的指令等合法文档内容仍可能被模型判为提示注入，
  导致 Extraction 被 `quality_gate` 阻断。
- 失败诊断增加了原因和处理建议，但未解决判定误报；当前仍需要人工核查来源。

### 9.2 关闭条件

1. 区分来源中的角色设定或被引用的指令与要求系统执行的注入指令，以固定正反例
   评估误报和漏报，并保留恶意样本的安全拒绝行为。
2. 覆盖文本、扫描件和不可变 Extraction 复用路径，确认重试不会绕过安全门禁。
