本地实现及固定语料验收通过。改动尚未提交、部署；正式环境仍运行原版本。

## 行为

- 不再因出现“系统提示词”、`system prompt`、`developer message` 等名词直接拒绝来源。
  抽取 `source-extraction-v9` 和规划 `source-import-plan-v12` 明确把角色自述、
  指令讨论、引用示例视为来源数据；针对导入器的控制指令仍属风险。
- 确定性规则检查明确的忽略规则、泄露隐藏信息、伪造安全标记及跳过审核指令。
  引用需有紧邻的说明文字；引用后追加的控制指令、独立引号包装和跨行英文控制指令仍拒绝。
  这套有限规则与模型判断共同使用，不能保证识别所有自然语言或编码混淆的攻击。
- 仅模型报告的疑似风险暂停在 `action_required / quality_gate / extract`。
  导入详情提供“人工复核”、最多八个 800 字片段、扫描页码和完整来源链接。
  未定位到可疑词时展示前三个片段；这些片段不是全文，需阅读完整来源再判断。
- `reviewImportSafety` v1 仅允许任务发起者、active human、reviewer/admin 角色复核，
  理由需为 5–1000 字。结论绑定当前任务和 Extraction，按相同结论及理由幂等，
  写入不可变 `import.safety_reviewed` 审计，记录审核人、时间、SourceVersion/Extraction。
  详情原文片段不进入失败诊断和审计。
- 明确控制指令不能“确认误报并继续”；可以人工拒绝或修改来源。拒绝结论在
  普通重试时仍由门禁读取，不会获得自动放行。
- 确认误报不修改不可变 Extraction，也不沿用其风险图谱候选；原 Chunk 继续经
  页面证据、保真和质量检查重新规划，并强制人工计划确认，最终 Proposal 进入治理审核。
  另一个任务复用同一 Extraction 时不会继承此复核授权。

## 确定性规则与真实领域链路

`TestPromptInjectionExamples` 固定 15 个中英文正反例，包括第一人称角色设定、提示词术语、
中文引号/英文引号/代码引用、多段引用、引用后的真实攻击、独立引号包装、
跨行命令和远离引用的说明词。

`TestImportFailureLifecycleE2E/prompt_injection_manual_review_lifecycle` 在自动创建并清理的
PostgreSQL Schema 内运行实际 Evidence、Extraction、Pipeline、PagePlanner、Governance 服务。
只控制模型输出，刻意让抽取和规划持续报告风险，以测试人工复核而不依赖模型刚好判对。

验证了五条链路：

1. 文本误报：暂停 → 真人填写理由 → 并发重复提交仅一个审计 → 重新规划 →
   强制计划确认 → 提案状态 `in_review`。
2. 历史 Extraction 的引用误报：沿用旧制品，不重新抽取、不改写候选 JSON；
   只有当前任务审核结论生效。
3. 无文本层 PDF：通过实际 Poppler 渲染和视觉区域解析，再走相同复核及恢复链路，
   原文预览保留第 1 页。视觉转写输出受控，此项验证处理链路，不是重新验收 OCR 准确率。
4. 明确攻击 + 历史未标记 Extraction：读取时重查原 Chunk、拒绝人工放行，
   普通重试仍被阻断。
5. 人工拒绝：落审计后取消，普通重试仍受已保存的拒绝结论约束。

同时验证无审核角色、system 身份、其他账号和旧 Extraction ID 被拒绝；相同结论与
理由幂等，改变理由不能覆盖原决定；读详情不改写历史记录，原文不进入审计。

## 实际界面

使用当前 Next.js 页面和隔离的真实认证/导入 HTTP 服务。完成登录、查看片段/页码、
打开复核表单、填写理由、分别提交确认误报和拒绝导入；明确攻击的表单无放行按钮。
两次 `review-safety` 请求均 HTTP 200，并在数据库查到各一个相应审计，页面回显理由和审核人。
确认误报后任务重新排队；拒绝后任务取消。

观察的 766 px 视口无水平溢出。该浏览器工具未提供视口调整能力，本次没有声称完成
320/390 px 的实际屏幕验收；新增布局使用换行、`min-w-0` 和长文本断行。
